# Content Creator — брифинг

> ⚠️ ВАЖНО: этот файл — единственный источник контекста. НЕ читать и НЕ использовать `CLAUDE.md` из родительских директорий (`poigraem/CLAUDE.md` и выше). Задачи основного магазина к этому проекту не относятся.

Отдельное веб-приложение в проекте «Поиграем». Инструмент для создания контента: коллажи обложек, сторис и TG-посты. Работает параллельно с основным магазином — всё что было в админке из этой области переедет сюда.

## Зачем отдельное приложение

В `index.html` основного магазина накопилось >6000 строк. Коллаж, сторис и TG-пост используются только Денисом (не клиентами), но грузятся всем. Вынос в отдельный файл:
- облегчает клиентскую загрузку основного магазина
- даёт чистый отдельный инструмент без лишнего UI
- не ломает основной магазин в процессе переработки

## Стратегия

1. **Этап 1 (сейчас):** создать рабочее приложение параллельно, не трогая основной магазин
2. **Этап 2 (после проверки):** вырезать соответствующие блоки из `index.html` + убрать `collage.js` и `story.js` из основного

## 📓 Журнал самообучения (методика — скилл `bot-selflearn-log`, сессия 63, 2026-09-02)

Собирает сырьё о том, чем инструмент пользуются на самом деле и что человек переписывает за ИИ.
Смысл извлекается ПОСТФАКТУМ (`node -e` по `*.jsonl`) — никакой классификации в рантайме.

- **Куда:** `POST https://api.poigraem.shop/cc/journal` (`requireAdmin`, тот же `cc_admin_token`),
  файлы `~/cc-journal/YYYY-MM.jsonl` на VPS, ретеншн 6 месяцев, потолок события 32 КБ.
  Env: `CC_JOURNAL_DIR` / `CC_JOURNAL_KEEP_MONTHS` / `CC_JOURNAL_ENABLED`.
  Свой каталог, а не общий с `~/catalog-journal`: там 17 тыс. `archive_restored` из цикла импорта.
- **Клиент:** внутри `content-creator.html` (`jEvent` / `jError` / `jAgg` / `jFlush`) — перенос
  обкатанного `poigraem/js/journal.js`. Буфер в `localStorage.cc_journal_buf` (до 300 событий),
  отправка пачками при 20 событиях / раз в минуту / при уходе со страницы (`pagehide`,
  `visibilitychange` — важно для телефона). Без токена события просто копятся в буфере.
- **События:** `session_start`, `used{feature}`, `search`, `generated`, `edited`, `published`,
  `rejected`, `error{stage}`, `hd_ok` / `hd_miss`, `cover_replace{source}`, `slot_transform`,
  `tpl_switch`, `el_add` / `el_delete` / `el_dup` / `el_layer`, `undo`, `prop_change`.
  Имена — из общей таксономии скилла, переименовывать нельзя: на них держится метод разбора.
- **chainId** — одна работа над одним артефактом (`post-…` / `collage-…` / `story-…`), заводится
  в `openTGPost` / `openCollage` / `openStory`. В каждом событии есть `device` (mobile/desktop) и `w`.
- **Правила, которые легко сломать:** (1) не вешать события на циклы (по играм, на перерисовку
  канваса) — так утонул журнал каталога; микроправки схлопывать через `jAgg`. (2) Снимки версии
  ИИ (`_ccPostBot`, `_stShortDescsAI`, `_stCapBot`) делать в момент генерации: правка человека
  пишется в те же переменные и затирает предложение модели навсегда. (3) base64 (лого 218 КБ,
  фото товаров, PNG) в журнал не тащить — `_jTrim` глушит, но поля выбирать осознанно.

### 2026-07-17 — Живые жалобы Дениса из браузера: CORS/404 пикера, апостроф-баг IGDB, WYSIWYG-редактор поста (сессия 58)

**Контекст:** первая сессия, где Денис сообщил о живых ошибках прямо из консоли браузера (`/session-start` без предыдущего контекста в диалоге — файл прочитан с нуля). Пять жалоб разом: (1) CORS/404 при поиске обложки через PS Store в консоли; (2) Marvel's Wolverine не получает HD-обложку в коллаже; (3) поле поиска в PS Store не подставляет название игры; (4) непонятное поле «сохраняется» с точками у токена; (5) пост нельзя редактировать, а копирование ломает ссылки (пример из реального поста показал сырой markdown `[Название](url)` рядом со словами).

**Что сделано (content-creator.html, коммит `45d7b59`, запушено):**
- **Фикс URL пикера PS Store/IGDB.** `_pickerPsSearch()` дёргал `${API}/price-lookup/api/admin/covers` — такого маршрута нет, отсюда 404 и маскирующий его CORS-щелчок в консоли. Разобрался через `git log -S` в `poigraem`: рабочий прокси `/pl/covers` был написан и задеплоен ещё в июне (`a391b71`), но правка была внесена в СТАРОЕ расположение файла (`poigraem/Standalone/content-creator/…`) — при переезде в отдельный репозиторий (`54af20a`) туда попала версия ДО этого фикса. Чистая регрессия миграции, не новый баг. Правка — одна строка URL.
- **Предзаполнение названия в пикере.** `_openPicker(target,i,title)` теперь пишет `_pickerTitle` и сразу подставляет его в поля `#cc-ps-q`/`#cc-igdb-q` (редактируемо, очищаются старые результаты поиска при открытии нового слота).
- **Убрана подпись «сохраняется» у токена** — перенесена в `title`-подсказку на самом поле.
- **Пост (#out-text): `<pre>` → `contenteditable` div, экран/буфер/отправка — одно и то же содержимое.** Раньше на экране был чистый текст без ссылок, а в буфер копировался СОВСЕМ ДРУГОЙ текст — markdown `[Название](url)`, который работает только через `parse_mode:'Markdown'` API, а при вставке куда угодно вручную (в TG-чат, в ВК) торчит скобками рядом со словом — это и была жалоба Дениса, с примером в чате. По требованию Дениса «ссылка должна быть вшита в текст, думай как» — решение: названия игр в редакторе стали настоящими `<a href>`; копирование (`copyOut`) кладёт в буфер сразу ДВА представления через `ClipboardItem`/`Blob` — `text/html` (реальный `<a>`, Telegram и другие rich-text редакторы при вставке превращают его в кликабельную ссылку прямо в слове) и `text/plain`-фолбэк `Название (url)` (для мест, не читающих HTML из буфера). Написан сериализатор `_outSerialize(mode)`, обходящий DOM `#out-text` и превращающий его либо в `[текст](url)`-markdown с экранированием спецсимволов (для `/api/tg-post`), либо в plain с URL в скобках (для буфера/счётчика символов). `_tgPostMd` и параллельные массивы `lines`/`linesMd` убраны — источник теперь один.
- Юнит-тест сериализатора на фейковом DOM (эмодзи+ссылка+перенос+подчёркивание в описании) — экранирование спецсимволов в тексте и сохранность самой ссылки подтверждены логикой (`node`, без jsdom/браузера).

**Найден, но НЕ починен (по решению Дениса — уйдёт в сессию основного магазина):**
- **Системный баг апострофа в IGDB-матчинге (`poigraem/backend/server.js`, функция `norm()`).** Разобрал жалобу про Wolverine до конца: в снапшоте название хранится с типографским апострофом `’` (U+2019), IGDB — с обычным `'` (U+0027). Прямая проверка API: `Marvel's Wolverine` (обычный) → `confidence:medium`, HD едет; `Marvel’s Wolverine` (типографский, как реально в снапшоте) → `confidence:low`, HD блокируется. Причина — `norm()` **удаляет** типографский апостроф («marvel’s»→«marvels», одно слово), а обычный **превращает в пробел** («marvel's»→«marvel s», два слова, второе слово «s» после фильтра длины теряется у `queryWords`, но остаётся у `nameWords`) — несовпадающая обработка ломает строгую проверку `queryWords.every(w=>nameWords.includes(w))`, и алгоритм скатывается в fallback-«угадывание» с низкой уверенностью, даже когда у IGDB есть точный матч. **Вероятно, задевает любую игру с притяжательным апострофом в названии** (Baldur's Gate, Dante's Inferno, Tom Clancy's и т.п.), не только Wolverine. Денис забрал этот пункт под починку в сессии основного магазина — здесь не трогали.

**Что решили:**
- Апостроф-баг — не чинить здесь, это `poigraem/backend/server.js`, отдельная сессия.
- Формат ссылок в посте — не «голый URL в скобках везде» (годится для ВК, но не для того, что Денис хочет видеть в Telegram), а именно вшитая в слово ссылка через rich-text буфер (`ClipboardItem` с `text/html`+`text/plain`) — прямой ответ на «думай как это сделаешь».
- Мелкие фиксы (URL пикера, предзаполнение, подпись токена) — делать все сразу, низкий риск, синхронно с большим фиксом поста.

**Новые баги:** апостроф-баг IGDB (см. выше, передан в другую сессию не как баг content-creator, а как баг основного магазина).

**Открытые вопросы:**
