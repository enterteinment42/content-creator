# Content Creator — брифинг

> ⚠️ ВАЖНО: этот файл — единственный источник контекста. НЕ читать и НЕ использовать `CLAUDE.md` из родительских директорий (`poigraem/CLAUDE.md` и выше). Задачи основного магазина к этому проекту не относятся.

Отдельное веб-приложение в проекте «Поиграем». Инструмент для создания контента: коллажи обложек, сторис и TG-посты. Работает параллельно с основным магазином — всё что было в админке из этой области переедет сюда.

## Зачем отдельное приложение

В `index.html` основного магазина накопилось >6000 строк. Коллаж, сторис и TG-пост используются только Денисом (не клиентами), но грузятся всем. Вынос в отдельный файл:
- облегчает клиентскую загрузку основного магазина
- даёт чистый отдельный инструмент без лишнего UI
- не ломает основной магазин в процессе переработки

## Стратегия

1. **Этап 1 (сейчас):** создать рабочее приложение параллельно, не трогая основной магазин
2. **Этап 2 (после проверки):** вырезать соответствующие блоки из `index.html` + убрать `collage.js` и `story.js` из основного

## 📓 Журнал самообучения (методика — скилл `bot-selflearn-log`, сессия 63, 2026-09-02)

Собирает сырьё о том, чем инструмент пользуются на самом деле и что человек переписывает за ИИ.
Смысл извлекается ПОСТФАКТУМ (`node -e` по `*.jsonl`) — никакой классификации в рантайме.

- **Куда:** `POST https://api.poigraem.shop/cc/journal` (`requireAdmin`, тот же `cc_admin_token`),
  файлы `~/cc-journal/YYYY-MM.jsonl` на VPS, ретеншн 6 месяцев, потолок события 32 КБ.
  Env: `CC_JOURNAL_DIR` / `CC_JOURNAL_KEEP_MONTHS` / `CC_JOURNAL_ENABLED`.
  Свой каталог, а не общий с `~/catalog-journal`: там 17 тыс. `archive_restored` из цикла импорта.
- **Клиент:** внутри `content-creator.html` (`jEvent` / `jError` / `jAgg` / `jFlush`) — перенос
  обкатанного `poigraem/js/journal.js`. Буфер в `localStorage.cc_journal_buf` (до 300 событий),
  отправка пачками при 20 событиях / раз в минуту / при уходе со страницы (`pagehide`,
  `visibilitychange` — важно для телефона). Без токена события просто копятся в буфере.
- **События:** `session_start`, `used{feature}`, `search`, `generated`, `edited`, `published`,
  `rejected`, `error{stage}`, `hd_ok` / `hd_miss`, `cover_replace{source}`, `slot_transform`,
  `tpl_switch`, `el_add` / `el_delete` / `el_dup` / `el_layer`, `undo`, `prop_change`.
  Имена — из общей таксономии скилла, переименовывать нельзя: на них держится метод разбора.
- **chainId** — одна работа над одним артефактом (`post-…` / `collage-…` / `story-…`), заводится
  в `openTGPost` / `openCollage` / `openStory`. В каждом событии есть `device` (mobile/desktop) и `w`.
- **Правила, которые легко сломать:** (1) не вешать события на циклы (по играм, на перерисовку
  канваса) — так утонул журнал каталога; микроправки схлопывать через `jAgg`. (2) Снимки версии
  ИИ (`_ccPostBot`, `_stShortDescsAI`, `_stCapBot`) делать в момент генерации: правка человека
  пишется в те же переменные и затирает предложение модели навсегда. (3) base64 (лого 218 КБ,
  фото товаров, PNG) в журнал не тащить — `_jTrim` глушит, но поля выбирать осознанно.

### 2026-07-31 — Мобильный редактор сторис починен по-настоящему; вёрстка карточек, логотип, правимые тексты (сессия 62)

**Контекст:** Денис с телефона: «вообще не работает редактор сторис, никакие тексты прописать нельзя — только в десктопной версии есть». То есть фикс сессии 60 (канвас 46vh) проблему НЕ закрыл, хотя числился сделанным.

**Что сделано:**
- **Диагностика стендом (по выбору Дениса из трёх путей — стенд / скриншот с телефона / сразу переделывать).** Собран `mobile-story.js` + `mobile-fix.js` (puppeteer-core, локальный HTTP-сервер, снапшот застаблен, эмуляция телефона 412×915 и 390×844 с touch). Корень найден точным замером: у `#st-tmpl-panel`/`#st-editor-panel` **инлайном** стояли `flex:1` + `overflow-y:auto`. В колоночной раскладке (`@media max-width:640`) `overflow!=visible` обнуляет `min-height:auto`, панель схлопывается до **65px при 395-496px контента**, а тело модалки при этом НЕ скроллится (`scrollHeight == clientHeight`, контент формально «влез») — до кнопок добавления элементов и полей ввода добраться физически нечем. Первая попытка фикса медиазапросом не сработала: инлайн-стиль нельзя переопределить без `!important` — правило перенесено в `<style>`, на мобильном собственный скролл панелей снят. Коммит `4bb62b3`.

До этого выбрать уже добавленный элемент можно было ТОЛЬКО точным тапом по канвасу ~200px шириной. Рендер повешен на `_stRenderSidebar`, поэтому добавление/удаление/дублирование/слои/Ctrl+Z обновляют список сами; вход в режим редактора теперь тоже рисует список и свойства. Подпись строки обновляется по мере набора текста. Коммит `4cf22b0` (там же — мобильная вёрстка: таблица игр давала 403px при экране 390, шапка 413px → скрыты справочные колонки «Валюта»/«📝», уменьшены паддинги, `#table-wrap{overflow-x:auto}`, шапка переносится на две строки; замер после: `scrollWidth 390 = innerWidth 390`).
- **Денис проверил вживую с телефона: «посмотрел, всё неплохо»** — впервые за три сессии мобильный сторис подтверждён на реальном устройстве.
- **Доработки по его же живым замечаниям (коммит `21ef554`):**
  - *Текст внутри карточки.* Развилка (распределить по высоте как в коллаже / обтянуть плашку по тексту / гибрид ~22%) — Денис выбрал **распределение**: название у верхней кромки плашки, цена и бейдж скидки у нижней, описание по центру между ними.
