# content-creator — указатель

Приложение подготовки контента для магазина: коллажи, сторис, посты в Telegram и ВК.
Работает в браузере, серверных процессов нет.

Этот файл грузится в КАЖДОЙ сессии, поэтому здесь только то, без чего нельзя начать:
описание задачи, открытые задачи строками и команды сессий.

| Файл | Что внутри | Когда читать |
|---|---|---|
| `CLAUDE-LOCAL-FOCUS.md` | чем занимаемся сейчас | грузится сам, импортом |
| `CLAUDE-LOCAL.md` | журнал сессий на Windows: лог и прежний «Текущий фокус» целиком | нужен ответ из прошлого |
| `CLAUDE-REFERENCE.md` | структура снапшота, что портируем из магазина, UI-концепция, стиль, методика журнала самообучения | нужна справка по устройству |
| `AUDITS-OPEN.md` | аудит текстового конвейера — незакрытые находки | берёшь находку в работу |
| `AUDITS-ARCHIVE.md` | закрытые аудиты и находки | `/session-audits-archive` |
| `SESSIONS-ARCHIVE.md` | записи лога старше пяти последних | `/session-archive` |

**Серверная сторона — отдельно и вне этого репозитория.** На VPS есть папка
`~/content-creator` со своим журналом `CLAUDE-VPS.md`: туда пишутся выводы по журналу
самообучения (`~/cc-journal`, 727 записей). Кода там нет. Журналов у проекта два,
они равноценны: **пиши в журнал той машины, на которой работаешь.**

**Как понять, где ты — по пути рабочего каталога:**
`D:\My Apps\content-creator` (любой windows-путь) — Windows, журнал `CLAUDE-LOCAL.md` здесь, рядом.
`/home/ubuntu/content-creator` — сервер, журнал `CLAUDE-VPS.md` там, в серверной папке.
⚠️ Не угадывай по операционной системе — смотри путь.

Импорт: @CLAUDE-LOCAL-FOCUS.md

## Зачем отдельное приложение

В `index.html` основного магазина накопилось >6000 строк. Коллаж, сторис и TG-пост используются только Денисом (не клиентами), но грузятся всем. Вынос в отдельный файл:
- облегчает клиентскую загрузку основного магазина
- даёт чистый отдельный инструмент без лишнего UI
- не ломает основной магазин в процессе переработки

## Стратегия

1. **Этап 1 (сейчас):** создать рабочее приложение параллельно, не трогая основной магазин
2. **Этап 2 (после проверки):** вырезать соответствующие блоки из `index.html` + убрать `collage.js` и `story.js` из основного

Единый HTML-файл (как `avito-helper.html`) — открывается через GitHub Pages.

Актуальный URL деплоя зависит от настроек Pages нового репо (ожидаемо `https://enterteinment42.github.io/content-creator/content-creator.html` — проверить). ## Данные

Источник игр — публичный снапшот магазина:
```
GET https://api.poigraem.shop/db/snapshot
→ { games: [...], subs: [...], ... }
```
Авторизация не нужна — снапшот публичный.

Для генерации TG-постов через Claude API:
```
POST https://api.poigraem.shop/api/claude
```
Токен не нужен (прокси открытый). Можно добавить `ADMIN_TOKEN` в localStorage если понадобится.
⚠️ Устарело: с SEC-1 `/api/claude` требует `requireAdmin` — токен из `localStorage.cc_admin_token` обязателен.

## Команда: /session-start

Когда Денис пишет `/session-start` или начинает новый чат с упоминанием проекта:
1. Прочитай раздел `## Текущий фокус`
2. Прочитай 2-3 последние записи в `## Лог сессий`
3. Резюмируй: «В прошлый раз остановились на [...]. Открыто [...]. Следующий шаг был [...].»
4. Спроси: «Продолжаем с этого или новое направление?»

## Команда: /session-end

Когда Денис пишет `/session-end`:
1. Обнови раздел `## Текущий фокус` вверху файла актуальным состоянием
2. Добавь НОВУЮ запись В НАЧАЛО раздела `## Лог сессий` (не редактируй существующие):
   - Дата (текущая)
   - Что сделано — конкретные изменения в коде/фичах
   - Что решили — архитектурные/продуктовые решения
   - Новые баги (если нашли) — с указанием файла
   - Открытые вопросы — что обсуждали но не решили
   - Что осталось — задачи на следующую сессию
3. Если в логе стало больше 5 записей — самые старые (сверх 5) перенеси в `SESSIONS-ARCHIVE.md` (в начало файла, создай его если нет). В CLAUDE.md всегда держим 5 последних сессий.
4. **Перенос закрытого в `AUDITS-ARCHIVE.md`** (создай файл если нет): пройдись по CLAUDE.md и найди аудиты/находки/задачи, которые за эту сессию стали ПОЛНОСТЬЮ закрытыми. Перенеси текст в `AUDITS-ARCHIVE.md` с пометкой «✅ закрыт, сессия N, коммит(ы) …», в CLAUDE.md оставь строку-указатель. ⚠️ Не переноси, если закрытие не подтверждено явно (код готов, но не проверено визуально — это НЕ закрытие по стандарту этого проекта).
5. **Проверка незакоммиченных/незапушенных правок:** выполни `git status --short` и проверку незапушенных коммитов (`git log --branches --not --remotes --oneline`), покажи список, напомни закоммитить/запушить. Не коммить сам без явной просьбы — только напоминание.
6. Спроси: «Что ещё зафиксировать?»

## Объём файлов памяти
