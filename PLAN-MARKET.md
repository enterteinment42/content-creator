# План роста до уровня рыночных инструментов — контент для малого бизнеса

Начат 25.09.2026. Сравнение — с планировщиками соцсетей (SMMplanner, Postmypost, SMMbox,
Buffer, Later, Metricool), конструкторами (Canva, Supa), ИИ-комбайнами (Predis.ai) и нишевым
TEDDEE. Метод — как у `avito-helper/PLAN-FOTOR.md`: направления с номерами, развилки решает
Денис, отдельный список «не берём».

**Аудитория — малый бизнес любого профиля**, не только красота: магазин инструментов,
ремонт телевизоров, пошив штор, пекарня, кофейня, мастер маникюра, массаж.

**Критерии отбора:** польза для владельца малого бизнеса, который ведёт соцсети сам и между
делом; не противоречит отстройке «живой человек, а не нейроглянец»; не ручной костыль;
не генерация «впрок» без повода в данных.

**Уже решено раньше (не пересматриваем):** продаём собранный продукт из модулей, копия на
клиента, а не общий сервис (`poigraem-backend/MODULAR-PRODUCT-PLAN.md`); порядок выхода —
чат-бот → «ведение соцсетей» (editorial + crosspost) → магазин; версия для чужих ниш —
отдельное приложение, а не сборка из файла магазина (решение по avito-helper, 22.09).

---

## Главный вывод

**Типы контента у всех одинаковые — различаются источник данных и частота.**
Новинка, акция, «до/после», кейс, отзыв, прайс, «сегодня есть / свободно» — это публикуют
и кофейня, и мастерская, и магазин. Поэтому шаблоны и генераторы строим **по типу
контента**, а нишу задают бренд-кит, словарь и источник данных. Шаблонов «под ноготочки»
не делаем.

**Наш козырь, которого нет у планировщиков:** контент рождается из данных клиента
(у нас — снапшот каталога). Тот же прайс питает и чат-бот, и посты: поменял цену один раз —
поменялось везде. Планировщики и Canva этого не умеют; TEDDEE умеет, но только для записи
к мастеру.

## Типы малого бизнеса

| Тип | Примеры | Откуда данные | Что публикуют | Как часто устаревает |
|---|---|---|---|---|
| **А. Товары** | инструменты, наш магазин, запчасти | МойСклад, 1С, YML-фид, Excel/Google-таблица, витрина Ozon/WB | новинки, поступления, скидки, подборки, «хит недели», наличие | дни |
| **Б. Запись на время** | маникюр, массаж, барбер, репетитор, фитнес | YCLIENTS, DIKIDI, Sonline | свободные окошки, мастера, «до/после», отзывы, прайс | часы |
| **В. Услуги по заявке** | ремонт ТВ, пошив штор, ремонт квартир, клининг | каталога нет: фото работ с телефона, заявки (amoCRM, Битрикс24, мессенджер) | кейс «что было → что сделали → срок → цена», «до/после», отзывы, прайс «от», сезонное, «почему ломается…» | недели |
| **Г. Общепит** | пекарня, кофейня | iiko, Poster, r_keeper | меню дня, «из печи в 8:00», новинки меню, «осталось 5 штук», акции по часам | часы |

**Канал, общий для всех офлайн-типов, — карточка на Яндекс Картах / 2ГИС.** Для кофейни
и мастерской он важнее Telegram. Публичного API публикаций Яндекс Бизнеса не найдено,
а с 2026 года публикации — часть платного тарифа (по обзорам, не проверено у Яндекса).

**Конкуренты по типам:** Б — TEDDEE (окошки из YCLIENTS/DIKIDI → сторис и посты,
автопубликация в TG и ВК, 665–2 399 ₽/мес за год). А — сервисы импорта YML/CSV в товары ВК
с автопостингом. Г — инструмента «меню и стоп-лист из iiko/Poster → посты» **не найдено**
(поиск не исчерпывающий). В — специализированных нет: закрывают агентства вручную.
Общие планировщики — SMMplanner от 990 ₽, Postmypost от 1 190 ₽, SMMbox от 500 ₽.

## Что у нас уже есть (не дублируем)

Контент из данных (снапшот магазина → посты, сторис, коллажи); ИИ-посты с контекстом из
описаний и «✂️ Сжать ИИ»; 8 шаблонов сторис + редактор элементов; коллажи; QR и ссылки
на карточку товара (`?game=<id>`); пресеты бренда (`BRAND_KEYS`); экспорт в нескольких
форматах; батч сторис; отправка в TG-канал с дублем в ВК; журнал самообучения
(что человек правит за ИИ); безопасная зона под подпись TG (сессия 68).

## Технические факты, проверенные 25.09

- **Сторис в Telegram ботом — только для бизнес-аккаунта.** Bot API `postStory` публикует
  от имени подключённого к боту бизнес-аккаунта (право `can_manage_stories`), не от канала.
  В сторис можно положить **кликабельную ссылку** (`StoryAreaTypeLink`) — это решает
  «текст на PNG не кликается». Для сторис канала нужен клиентский API (сессия пользователя) —
  другой класс риска.
- **Сторис ВК от имени сообщества** — через API (`stories.getPhotoUploadServer` с `group_id`).
- **Публикации Яндекс Бизнеса** — публичного API не найдено: только выгрузка «готово к вставке».

## М1. Планирование и очередь постов — ⬜

Контент-план с отложенной публикацией есть у всех планировщиков. У нас — **не строить свой
планировщик**: в editorial-боте расписание уже есть (черновики и расписание в JSON на сервере).
content-creator отдаёт пост в очередь бота.
**Сначала:** прочитать `editorial-bot.js` на сервере — как устроены расписание и приём постов.
Все типы.

## М2. Источник данных как сменный модуль — ⬜

Сейчас источник один — снапшот магазина. Под продажу — адаптер с единым форматом
«позиция: название, цена, фото, описание, наличие, ссылка» + события.
Порядок адаптеров: **Google-таблица / CSV** (закрывает минимум у всех четырёх типов и
годится мастерской — прайс «от») → YML-фид (А) → по первому клиенту: МойСклад (А),
YCLIENTS/DIKIDI (Б), iiko/Poster (Г).
⚠️ Адаптер под систему — только под реального клиента, не «впрок».

## М3. События в данных → черновик — ⬜

Главная автоматизация: повод для поста появляется в данных, а не в голове владельца.
А — новинка, снижение цены, снова в наличии, конец акции. Б — свободные окошки на завтра.
Г — меню дня, новинка меню. В — закрытая заявка с фото → кейс.
**Черновик в очередь, публикует человек** (или с автопубликацией по согласию) — иначе
теряется живой голос, а журнал самообучения перестаёт видеть правки.
**Пилот на себе:** события из снапшота магазина (новинки, скидки PS Store).

## М4. Бренд-кит — ⬜

Логотип, палитра, шрифты, тон текста — подставляются во все шаблоны и промпты.
Есть у Canva и Predis; у нас пресеты бренда — набор ключей, не карточка бренда.
Для продажи обязательно: у каждого клиента свой стиль. Перекликается с Ф4 avito-helper —
решения держать общими.

## М5. Шаблоны по типу контента — ⬜

Не «ниши», а типы: карточка позиции, подборка, акция с датой окончания, «до/после»,
кейс (было → сделали → срок → цена), отзыв, прайс, «сегодня есть / свободно», FAQ.
Нынешние 8 шаблонов сторис заточены под игры — переделка «с Claude design» (уже
запланирована) должна выпустить их типовыми, с безопасной зоной TG.

## М6. Каналы публикации — ⬜

Есть: TG-канал, ВК (кросспост). Добавить по мере пользы: **MAX** (SMMplanner и SMMbox уже
умеют — для российских клиентов в 2026 это плюс); **сторис ВК** через API; **сторис TG** через
бизнес-аккаунт с кликабельной ссылкой; **Яндекс Карты / 2ГИС** — выгрузка «готово к вставке»
(текст + картинка под их формат), публикует человек.
**Развилка:** сторис TG — бизнес-аккаунт (официально, но только личный профиль владельца)
или клиентский API для канала (сессия пользователя на сервере — риск блокировки аккаунта).

## М7. Аналитика переходов — ⬜

Планировщики показывают охваты, но не видят продаж. У нас ссылки ведут в наш же магазин
(`?game=<id>`): считаем «пост / сторис / QR → переходы → заказ» — метка источника в ссылке
и счётчик на стороне магазина. Для клиентов без сайта — короткая ссылка-переадресация
со счётчиком. Лучшее время публикации — позже, когда накопятся данные.

## М8. Анимированные сторис — ⬜

Supa и Predis делают видео, у нас только PNG. Без генерации видео нейросетью: оживить
наш же шаблон (медленный наезд на фото, появление цены) и записать MP4 в браузере.
Сторис-видео заметнее в ленте.

## М9. Согласование и несколько клиентов — ⬜

Нужно, если Денис сам ведёт соцсети клиента («ведение соцсетей» из модульного плана):
пост ждёт одобрения клиента, у каждого клиента свой набор аккаунтов. Есть у Postmypost и
SMMplanner. Не нужно, если клиент ведёт соцсети сам. Зависит от модели продажи — развилка ниже.

## М10. Мобильный ввод: фото работы → кейс — ⬜

Для типа В (и «до/после» в Б): мастер после работы отправляет фото боту в Telegram
с парой слов — получает готовый кейс в очередь. Без открытия редактора на ПК.
Естественно ложится на editorial-бота, который уже принимает посты из TG.

## М11. Отзывы → карточки — ⬜

Отзыв клиента → картинка для сторис/поста. Нужно Б, В, Г. Официального API отзывов
Яндекс Карт / 2ГИС для этого не найдено — вставка текста руками или отзывы из своего бота.

## М12. Ответы на комментарии силами ИИ — ⬜ (в связке с чат-ботом)

Есть у Postmypost. У нас не делать вторым ботом: это модуль чат-бота, продаётся в комплекте.

## Порядок (рекомендация)

**Этап 0 — на своём магазине, обкатка механики:** М1 → М3 (события из снапшота) → М7.
Полезно сразу и проверяет цепочку «данные → черновик → очередь → публикация», на которой
стоит всё остальное.

**Этап 1 — фундамент под продажу, без привязки к нише:** М2 (адаптер Google-таблица/CSV) →
М4 → М5 (вместе с переделкой шаблонов) → М6 (проверка сторис ВК и TG).

**Этап 2 — под первого клиента:** адаптер его системы из М2, М10 или М11 по его типу,
М9 если ведём соцсети за него, М8 по спросу.

---

## Развилки для Дениса

1. **Модель продажи:** клиент ведёт соцсети сам (инструмент) или Денис ведёт за него (услуга)?
   Решает, нужен ли М9 и насколько простым должен быть интерфейс.
2. **Первый клиент какого типа (А/Б/В/Г)?** Решает, какой адаптер М2 и что из М10/М11 первым.
3. **Content-creator для клиентов — отдельное приложение, как решено для avito-helper,
   или общий инструмент с модулями?** По аналогии — отдельное, но стоит подтвердить.
4. **Сторис TG:** бизнес-аккаунт или клиентский API (см. М6).

## Не берём

- Анализ конкурентов по чужим аккаунтам (Predis) — не про малый бизнес «между делом»
- Управление рекламой (Metricool) — отдельная профессия и отдельный продукт
- 13 соцсетей — берём только то, где сидят клиенты малого бизнеса в РФ и КЗ
- Превью сетки Instagram и ссылка в профиле (Later) — Instagram не основной канал аудитории
- ИИ-генерация видео и «улучшение» фото работ нейросетью — для «до/после» и кейсов это
  обман клиента, против отстройки «живой человек, а не нейроглянец»
- Пакетная генерация постов «на месяц вперёд» без повода в данных — против критериев
- Шаблоны под конкретные ниши («ноготочки», «шторы») — нишу задают бренд-кит и данные
